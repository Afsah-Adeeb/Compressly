02

What happens to those bytes

Five stages, each one independently testable. The middle three are the compressor proper; the outer two are what make it usable on files bigger than memory.

01 · SPLIT

Independent blocks

1 MiB each, no shared history or trees. That independence is what buys both streaming and parallelism.

02 · LZ77

Match finder

32 KiB sliding window, hash-chain index over 3-byte prefixes, lazy matching. Repeats become (distance, length).

03 · HUFFMAN

Canonical codes

Two alphabets — literals/lengths and distances. Only code lengths ship; both sides rebuild the same table.

04 · POOL

Thread pool

Hand-written, ~80 lines. Blocks are handed out by index and reassembled in order, so output never depends on thread count.

05 · FRAME

Self-describing

Every block records its own length and method. The decoder needs nothing agreed out of band.

04

Where the parallel speedup stops

3.71× at 8 threads on a 4-core i5-10300H — not 8×, and the curve turns over after that. Knowing why is the point of measuring it.

Four physical cores, eight logical. The 4→8 gain is hyperthreading filling memory stalls in the hash-chain walk; past 8 you are oversubscribing the same execution units and paying in context switches. The single-thread number is the one compared against gzip above, because gzip is single-threaded and anything else would be a rigged comparison.

05

Decisions worth defending

Every one of these was a fork in the road with a measurement attached.

BOUNDED MEMORY
A 636 MB file compresses in 44 MiB of RAM. Footprint tracks block size, never file size.
DETERMINISM
1 thread or 8, streaming or in-memory — byte-identical output. Frequency ties break on symbol index. A test asserts it.
TRUST NOTHING
The decoder never believes the header. Every allocation is bounded by what the payload could actually encode; every read is bounds-checked.
BLOCK SIZE
1 MiB, chosen by sweep. At 64 KiB the ratio drops 0.77 pts — 122 blocks paying for 122 code-length tables.
C ABI
This page talks to the C++ through a flat C ABI via ctypes. No exception may cross it; every entry point returns a status code.
KNOWN GAP
gzip is ~2× faster per thread. Four measured causes, none algorithmic — table-driven decoding and compressed code-length tables are the open wins.
